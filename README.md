# CS Response Widget

Виджет на рабочий стол amoCRM: почасовое распределение обращений и
среднее время первого ответа по воронке **Customer Success**, только по
4 сотрудницам.

Никаких вебхуков — сервер сам идёт в amoCRM API при каждом открытии
виджета и считает всё заново за «вчера». Это проще в развёртывании,
чем вебхук-based вариант, и для десятков сделок в день работает быстро.

## Как это устроено

```
[amoCRM API v4] <--- server.js (Node/Express) ---> [widget.html] ---> вставляется
                         GET /api/stats                                как iframe-виджет
                                                                        на рабочий стол
```

- `GET /api/v4/leads` — сделки, созданные вчера в воронке → часовая разбивка.
- `GET /api/v4/events` (`type=incoming_chat_message,outgoing_chat_message`) —
  переписка по этим сделкам → время от первого входящего до первого
  следующего исходящего = время первого ответа, усреднённое по
  ответственному сотруднику.

## ⚠️ Что стоит проверить перед боевым использованием

Я собрал это без доступа к вашему API «вживую» (у меня нет сети из
песочницы), поэтому:

1. **Проверьте сырой ответ `/api/stats`** сразу после первого запуска —
   откройте его в браузере и посмотрите, что реально приходит от
   amoCRM в `/api/v4/events`. Названия полей события (`type`,
   `entity_id`, `created_at`) взяты из документации amoCRM v4 и
   практики других интеграторов, но нюансы (например, как именно
   помечается направление сообщения) стоит свериться на реальных
   данных.
2. Время ответа считается как «от первого входящего сообщения по
   сделке до первого следующего исходящего», привязанное к
   **ответственному сделки**, а не к автору конкретного сообщения —
   amoCRM Events API не всегда отдаёт автора сообщения напрямую.
   Если сделка была переназначена посреди разговора — цифра будет
   приблизительной.

## Установка

```bash
cd cs-response-widget
npm install
cp .env.example .env
```

Заполните `.env`:

1. **AMO_SUBDOMAIN** — ваш поддомен (`bitkoganfinance`).
2. **AMO_ACCESS_TOKEN** — долгосрочный токен:
   Настройки → Интеграции → ваша приватная интеграция → «Ключи и
   доступы» → «Создать долгосрочный токен». Если приватной интеграции
   ещё нет — создайте: Настройки → Интеграции → Создать интеграцию.
3. **PIPELINE_ID** — уже проставлен (`7163002`, Customer Success).
4. **EMPLOYEE_IDS** — уже проставлены 4 id, но перепроверьте их: они
   были взяты из адресной строки при фильтрации по менеджерам; если
   сомневаетесь — сверьте через `GET /api/v4/users`.
5. **TIMEZONE** — по умолчанию `Europe/Moscow`, поменяйте, если у
   аккаунта другой часовой пояс.

Запуск локально для проверки:

```bash
npm start
# сервер поднимется на http://localhost:3000
# откройте http://localhost:3000/api/stats — должен вернуться JSON
# откройте http://localhost:3000/widget.html — должен отрисоваться график
```

## Развёртывание

Нужен любой Node-хостинг с HTTPS (обязательно — amoCRM не встроит
виджет по http, будет заблокировано как mixed content):

- Render.com / Railway.app — просто подключить репозиторий, задать
  переменные окружения из `.env`, деплой в пару кликов, HTTPS из коробки.
- Свой VPS — `pm2 start server.js`, nginx как reverse proxy +
  Let's Encrypt (`certbot`).

После деплоя у вас будет публичный адрес вида
`https://ваш-домен/widget.html`.

## Добавление на рабочий стол amoCRM

1. Рабочий стол → навести на пустую плитку → нажать **+**.
2. **Добавить новый виджет**.
3. Вставить ссылку `https://ваш-домен/widget.html`.
4. Задать ширину/высоту (рекомендую 400×420).
5. Сохранить.

Виджет сам обновляется каждые 5 минут, пока открыт, плюс подтягивает
свежие данные при каждом открытии страницы.
